# 01 スモークテスト（約5分・両OS）

リリース前・月次に必ず実施する最小セット。1つでも NG ならリリースを止め、該当分野の詳細チェックリストへ進む。

## 起動

- [ ] **SMK-01 プラグイン読込**
  - 手順: Obsidian を起動（または プラグインを再読込）。開発者ツールの Console を開く。
  - 期待: エラーが出ない。リボンに録音アイコン（circle-dot）が表示される。

- [ ] **SMK-02 doctor 全OK**
  - 手順: コマンドパレット →「診断を実行（doctor）」。
  - 期待: すべて [OK]（環境起因の [WARN] は既知のものだけ）。

## 録音の基本フロー

- [ ] **SMK-03 both 録音 → 停止 → 再生確認**
  - 手順: 録音ビューを開き、Source=両方 で録音開始。音楽/動画を20秒再生しつつ時々発話 → 停止。
  - 期待: `.m4a` が保存先に生成され、**システム音と自分の声の両方**が聞こえる。音量が極端に小さい/大きい/割れていない。

- [ ] **SMK-04 ノート埋め込み**
  - 手順: SMK-03 の停止後（「停止時にノートに埋め込み」オンの状態）。
  - 期待: 選択したノートに `![[...]]` が挿入され、プレイヤーで再生できる。

- [ ] **SMK-05 状態ファイルの後始末**
  - 手順: SMK-03 の停止後、状態ディレクトリ（既定 `~/.meeting-recorder/sessions`）を確認。
  - 期待: セッションの `.pid` / `.status` / `.control` / `.level` と中間ファイル（sys/mic）が残っていない。

## 文字起こし

- [ ] **SMK-06 文字起こし1件**
  - 手順: 保存した録音ファイルを右クリック →「文字起こし（RMR）」→ モーダルでモデル/言語を確認して実行。
  - 期待: 進捗が表示され、完了後にトランスクリプトが挿入される。内容が音声とおおむね一致する。
