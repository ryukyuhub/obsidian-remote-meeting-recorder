# 04 堅牢性（クラッシュ復旧・remix・sweep・約15分・主に macOS）

「録音データを絶対に失わない」の実機確認。状態機械のロジック自体は `npm run test:e2e`（ニセバイナリ）でカバー済みなので、ここでは**実プロセス・実 Obsidian をまたぐ挙動**を確認する。

外部プロセス（sysrec）前提の項目は macOS のみ（`[mac]`）。Windows の Web 経路はプロセスをまたげない設計のため、対応する堅牢性テストは [03-recording-windows.md](03-recording-windows.md) の WIN-07 / WIN-08（graceful stop・中断セッション後始末）でカバーする。

## Obsidian をまたぐ録音

- [ ] **ROB-01 録音中の Obsidian 強制終了 → 復元（active）** `[mac]`
  - 手順: both で録音開始 → 音を鳴らしたまま Obsidian を**強制終了**（Cmd+Opt+Esc）→ 30秒待つ → Obsidian 再起動。
  - 期待: sysrec は生き続けて録音が継続しており、再起動後に録音ビューが**録音中として復元**される（elapsed 継続）。停止すると強制終了中の音声も含めて保存される。

- [ ] **ROB-02 プラグイン unload で録音を殺さない** `[mac]`
  - 手順: 録音中にプラグインを無効化 → 数十秒後に有効化。
  - 期待: 録音は継続しており（sysrec はレンダラより長生き）、有効化後にセッションが復元される。

## クラッシュ後の復旧

- [ ] **ROB-03 sysrec 死亡＋中間ファイルあり → 復旧** `[mac]`
  - 手順: both で録音中に `kill -9 <sysrec の pid>`（`.pid` ファイルで確認）→ Obsidian を再起動。
  - 期待: 復旧待ちとして検出され、ステータスバーに「⚠ 未保存の録音 1 件」、録音ビュー上部に対象の日時・長さ付き復旧バナーが出る。バナーの「復旧」ボタン（またはコマンド「保存が完了しなかった録音を復旧」）で mix が完了し、`.m4a` が生成されてバナーが消える。

- [ ] **ROB-03b 復旧待ちが 2 件あるとき両方復旧できる** `[mac]`
  - 手順: ROB-03 を 2 回繰り返して復旧待ちを 2 件ためる → Obsidian を再起動。
  - 期待: ステータスバーが「⚠ 未保存の録音 2 件」。バナーに 2 行出て、それぞれの「復旧」ボタンで個別に復旧できる（片方を復旧しても、もう片方が残る）。コマンドから実行した場合は選択ダイアログが出る。

- [ ] **ROB-03d 録音の尺と音程が実時間どおり（早送りが起きない）** `[mac]`
  - 手順: 440Hz の正弦波を再生しながら `both` で 40 秒以上録音して停止。可能なら CPU 負荷をかけた状態でも実施。
  - 期待: `.m4a` の尺が実測の録音時間と ±1 秒以内で一致し、録音されたトーンが **440Hz ±3Hz**（早送りだと 470〜480Hz になる）。sysrec のログの system / mic フレーム数がほぼ一致する。取りこぼしがあれば「取りこぼし …秒（…%）を無音で補完」がログに出る（無言で壊れないこと）。

- [ ] **ROB-03e 44.1kHz 出力（Bluetooth イヤホン）でも等間隔の無音が入らない** `[mac]`
  - 手順: 出力先を 44.1kHz のデバイス（BT イヤホンなど。`system_profiler SPAudioDataType` の Current SampleRate で確認）にして、440Hz の正弦波を再生しながら 60 秒録音して停止。録音中にイヤホンを通話モードへ入れる（BT マイクを使うアプリを起動する等）とレート追従も確認できる。
  - 期待: sysrec のログに「取り込みレートをデバイス実測へ補正（タップ報告 48000Hz → 実 44100Hz）」が出て、**取りこぼしの警告が出ない**。トーンは 440Hz ±3Hz。録音中にレートが変わった場合は「出力の変更に追従して再接続（… 44100Hz → … 16000Hz）」が出て、その後も取りこぼしが増えない。
  - 補足: この補正が無いと 8.1%（1 − 44100/48000）ぶん実時刻に追いつけず、**0.25 秒ごとに 10〜20ms の無音**が入り「速い＋プツプツ切れる」録音になる（0.11.0 で発生）。ffmpeg での検出: `ffmpeg -i <file> -af silencedetect=n=-60dB:d=0.005 -f null -` が等間隔の無音を大量に出さないこと。

- [ ] **ROB-03f 既定入力が Bluetooth でもマイクが録れる** `[mac]`
  - 手順: マイク選択を「既定の入力デバイス」（＝`--mic-device` 無し）にし、システム既定入力を BT イヤホンにして `both` で 15 秒録音。
  - 期待: sysrec のログの `mic=` フレーム数が **0 でない**（system とほぼ同数）。「⚠ マイク: 1 フレームも取得できませんでした」が出ないこと。経路が切り替わった場合は「⚠ マイク: 3秒間 1 バッファも取得できませんでした。取得経路を切り替えます」が出て、その後フレームが増える。
  - 補足: 既定入力が BT のとき AVAudioEngine 経路はバッファが 1 つも流れず、**会議まるごと無音**になっていた（0.11.0 まで。2026-07-28 19:17 の実害）。既定入力でも IOProc 経路を優先することで解消。

- [ ] **ROB-03c 長時間録音でも mix が完了する** `[mac]`
  - 手順: both で 60 分以上録音して停止する（または既存の長尺中間ファイルで ROB-03 の復旧を実施）。
  - 期待: mix が数十秒程度で終わり `stopped` になる。書き出しは分割して行うため、長さに対して処理時間が急増しない（分割前は 73 分の録音で 20 分以上かかっても完了しなかった）。

- [ ] **ROB-04 SessionWatcher による外部停止の検出** `[mac]`
  - 手順: 録音中に Obsidian は開いたまま `kill <sysrec の pid>`（SIGTERM）。
  - 期待: 数秒以内に watcher が検出して自動 finalize され、それまでの録音が保存される（通知が出る）。

- [ ] **ROB-05 蓋閉じ（クラムシェル）** `[mac]`
  - 手順: 録音中に MacBook の蓋を閉じて10秒 → 開く。
  - 期待: 録音が失われない。継続していれば続行、停止されていれば finalize 済みでファイルが確定している。

## 中間ファイルの温存

- [ ] **ROB-06 孤児 sweep が remix 待ちを消さない** `[mac]`
  - 手順: ROB-03 の状態（死亡＋中間あり）で remix せずに新しい録音を開始。
  - 期待: 開始前の sweep で remix 待ちセッションの中間ファイルが**温存**され、新規録音も正常に開始できる。その後 remix で復旧できる。

- [ ] **ROB-07 二重停止の冪等性**
  - 手順: 停止ボタンを素早く2回押す／停止コマンドと停止ボタンを同時に実行。
  - 期待: finalize は1回だけ実行され、エラーや二重 mix が起きない。

## ログ

- [ ] **ROB-08 ログ退避とローテーション** `[mac]`
  - 手順: 状態ディレクトリの `logs/` を確認。
  - 期待: 削除されたセッションのログが退避されている。30日超の古いログは起動時に自動削除されている。
