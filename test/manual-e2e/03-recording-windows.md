# 03 Windows 録音（Web Audio 経路・約15分）

Win32Backend（`getDisplayMedia` loopback + `getUserMedia` + MediaRecorder）の実機確認。数値レベルの詳細診断は `dev/win-audio-diag.js`（`Windows検証手順.md` 参照）を併用する。

前提: ビルド成果物（main.js / styles.css / manifest.json）を G: の vault へコピー→Obsidian リロード済み。

## 録音の基本

- [ ] **WIN-01 both 録音（ループバック＋マイク）**
  - 手順: 音源=両方 で録音。音楽/動画30秒＋時々発話 → 停止 → 再生。
  - 期待: システム音と自分の声の両方が聞こえる。ファイル形式は m4a（AAC 非対応環境では .webm フォールバックでも可）。

- [ ] **WIN-02 システム音のみ / マイクのみ**
  - 手順: 音源=system と音源=mic でそれぞれ短く録音。
  - 期待: 指定したソースのみが録れている。

- [ ] **WIN-03 取り込み時正規化の収束**
  - 手順: AGC オンで both 録音。小さめの音源と大声を混ぜる → 停止。
  - 期待: 仕上がりが -14dBFS 近傍（合格ライン -16〜-12dBFS、耳で「小さすぎ/割れ」がない）。

- [ ] **WIN-04 出力音量からの独立**
  - 手順: 録音中に Windows の出力音量を半分に下げる。音源は同じ音量で再生し続ける。
  - 期待: 録音物のレベルが出力音量に引きずられない（ループバックは出力音量と独立、または正規化で吸収）。

- [ ] **WIN-10 ノイズゲート（無音カット）**
  - 手順: 録音ビューで「マイクゲート」標準（-40）にして音源=mic で録音。無音区間（5秒以上）と発話を交互に → 停止。自動ゲインはオン/オフどちらでも効く（両方試すなら尚可）。
  - 期待: 無音区間のホワイトノイズ/環境音が抑えられ、発話は欠けない（MAC-07 と同等）。特に**発話の頭が切れないこと**（Windows はゲート判定が最大 0.1 秒粗いため要耳確認）。ゲート「オフ」なら無音区間にも環境音がそのまま残る。

## デバイス・耐性

- [ ] **WIN-05 録音中の出力デバイス切替**
  - 手順: both 録音中に出力デバイスを切り替える（スピーカー→ヘッドホン等）。
  - 期待: 追従して録音継続。トラックが ended になった場合は fail-safe（録音停止＋ファイル確定）でも許容。**`-inf` のまま無反応は NG**。

- [ ] **WIN-06 無音ウォッチ（ソース別）**
  - 手順: (a) マイクをミュートして音源=mic で録音開始。(b) 何も再生せず・マイクをミュートして音源=両方 で録音開始。(c) 何も再生せず、マイクには話しかけながら音源=両方 で録音開始。
  - 期待: どの場合も**録音は継続**し、通知はソースごとに最大 1 回。
    - (a) **5 秒**で「⚠ マイクのレベルが 0 のままです。…（マイク権限・入力デバイスを確認してください）。録音自体は継続しています。」
    - (b) **5 秒**で「⚠ システム音声とマイクのレベルが 0 のままです。…」が 1 回だけ。20 秒時点でシステム音声の通知が重ねて出ないこと。
    - (c) 5 秒では何も出ず、**20 秒**でシステム音声の通知。既定の再生デバイスと既定の通信デバイスが同じ機器なら「システム音声のレベルが 0 のままです。会議の音声がまだ流れていなければ問題ありません（システム音声は Windows の既定の再生デバイス『…』だけを録音します）。」（⚠ なし）。別の機器なら WIN-11 の強い文言。
    - 途中で音を鳴らした・話したソースは、その時点で監視対象から外れて通知されない。

- [ ] **WIN-11 既定の再生デバイスと既定の通信デバイスのずれ（システム音声だけ無音）**
  - 前提: 再生デバイスが 2 つ以上ある（例: 内蔵スピーカー＋USB/Bluetooth ヘッドセット）。Google Meet のテスト通話（`meet.google.com` の「マイクとスピーカーをテスト」等）を使えると望ましい。
  - 手順:
    1. Windows の「サウンド」設定（コントロール パネルの「サウンド」→ 再生）で、**既定のデバイス**と**既定の通信デバイス**を別の機器にする → 診断を実行。
    2. 両方を同じ機器に戻す → 診断を実行。
    3. 再び別の機器にし、Meet の 設定 → 音声 → スピーカー を**通信デバイス側の機器**にする → 音源=両方 で録音開始し、Meet の音を鳴らしつつマイクにも話す。20 秒以上待ってから停止 → 再生。
    4. Meet のスピーカーを「既定」に戻して 3 と同じく録音 → 停止 → 再生。
  - 期待:
    - 1: 「システム音声の録音元（再生デバイス）」が **[WARN]**。説明に既定の再生デバイスと既定の通信デバイスの**両方の名前**、「会議アプリ（ブラウザの Meet など）のスピーカー設定を『既定』に」、Windows の「サウンド」設定で通信デバイスを揃える方法が出る。
    - 2: 同項目が **[OK]**（「既定の再生デバイス『…』の音を録音します（既定の通信デバイスも同じ機器です）。」）。
    - 3: 開始時にずれの Notice は**出ない**。開始から **20 秒**で「⚠ システム音声のレベルが 0 のままです。会議の音声が録音されていない可能性があります（録音自体は継続しています）。」＋両デバイス名入りの案内が 1 回出る。録音は継続し、マイクの声は録れている。開発者ツール Console に `既定の再生デバイスと既定の通信デバイスが異なります` の warn（トラック label・`getSettings()`・両デバイス名入り）が出ている。
    - 4: システム音声（Meet の音）が録れている。システム無音の通知は出ない。
  - 補足: 3 でシステム音声が録れてしまった場合も結果として記録する（Chromium の loopback が既定の再生デバイスのみを録るのはソース上の事実だが、Meet で無音になった報告の原因としては未確定のため、この結果が仮説の検証になる）。診断が [INFO]（判定不能）になった場合は、Console の `enumerateDevices()` の `audiooutput`（`default` / `communications` の label と groupId）を結果に貼る。

- [ ] **WIN-07 プラグイン再読込 / Obsidian 終了時の graceful stop**
  - 手順: 録音中にプラグインを無効化→有効化（別途: 録音中に Obsidian を通常終了）。
  - 期待: 録音は graceful stop され、**それまでの音声がファイルとして確定**している（Web 経路はプロセスをまたげないため、途中までのデータが残れば合格）。

- [ ] **WIN-08 中断セッションの後始末**
  - 手順: WIN-07 の後に Obsidian を再起動。
  - 期待: 中断セッション（interruptedWeb）の状態ファイルが後始末され、部分ファイルは保存されている。孤児が残らない。

## 診断スクリプト（大きな変更後のみ）

- [ ] **WIN-09 win-audio-diag.js**
  - 手順: 開発者ツール Console で `dev/win-audio-diag.js` を実行（約75秒、指示に従う）。
  - 期待: 最後の JSON で [A] mp4/AAC 可否、[B] マイク健全、[C] ループバック取得、[D] 正規化収束、[E] 出力独立、[F] デバイス切替追従 が想定どおり。JSON を結果ファイルに貼る。
