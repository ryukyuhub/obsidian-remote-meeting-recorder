## 0.10.1

### 修正（重要）

- **録音が早送りになる問題を修正**。会議録音の中身が実時間より短く詰まり、相手の声が早回しで再生される（実例では 42 秒の録音が 14 秒に圧縮）不具合。以前から起きていたもので、実際の失敗録音の解析と再現実験で原因を特定した。
  - **原因**: システム音の時間軸を「書き込めたフレーム数の累積」で決めていたため、取りこぼしが無音の穴にならず後ろが前に詰まり、欠損率がそのまま再生速度になっていた。440Hz のトーンを録って測ると 479Hz（1.0886 倍）で戻ってきた。
  - **取りこぼしの発生源**: リアルタイムのオーディオコールバックの中で、フォーマット変換・ゲイン・AGC/リミッター・ファイル書き込みまで同期実行していた。バッファ周期（10.67ms）を超えると macOS がその周期を捨てるため、CPU 負荷が高いほど欠損が増える。Obsidian・マイク・クラウド同期・自動文字起こしが同時に走る実運用では取得率が 33% まで落ちていた。**「連続して録音すると失敗する」のは、直前の録音の mix や文字起こしがまだ走っていて負荷が高いため。**
  - **対処**: 取り込みをソースごとの専用スレッドに分離し、オーディオコールバックはコピーして渡すだけにした。あわせて時間軸を各バッファの実時刻基準に変更したので、万一取りこぼしてもその区間が無音になるだけで、早送りにはならずマイクとの同期も保たれる。
  - ⚠️ **これは `sysrec` バイナリ側の修正です。** doctor の「sysrec を取得」または `npm run build-sysrec` で更新してください。更新後は `--version` が `0.10.1` を返します。
- **取りこぼしが起きたときにログと警告を出すようにした**。従来は完全に無言だったため、録音を聞き直すまで誰も気づけなかった。全体の 1% を超える取りこぼしは警告として記録される。
- **sysrec の版数表示が更新されない問題を修正**。手書き定数だったため 0.9.0・0.10.0 と 2 回続けて `0.8.0` のまま出荷しており、バイナリを入れ替えても更新できたか判別できなかった。ビルド時に manifest.json から生成するようにした。

### 検証

- CLI: 440Hz のトーンが 479Hz → **440.0Hz**（速度比 1.0000）。全 10 コアに CPU 負荷をかけた状態でも維持。
- Obsidian 実機で `both` 録音を連続 2 回: ファイルの尺が実測と一致（55.999 秒 / 55.829 秒）、周波数 440.0Hz / 439.5Hz、システム音とマイクのフレーム数の差 0.5%、取りこぼし警告なし。
- fake-binary E2E 76 件 pass、build / eslint 0 error。
