## 0.11.7

**プラグイン本体だけ更新されて `sysrec` バイナリが古いまま取り残される**問題を、診断（doctor）で気付けるようにしました。

0.11.6 のリリースノートに「入れ替えないと今回の修正は効きません」と書いていましたが、**自動では何も促されない**ため実際に取り残されました。2026-08-15 の 73 分の会議録音が、直したはずの「1 秒に 4 回プツプツ切れる」状態（**356 秒＝8.1% が無音**）で記録されています。診断は当時 `v0.10.1（abi 2 / 要求 2 以上）` を **[OK]** と表示していました。

### 改善

- **診断（doctor）が、`sysrec` バイナリの版数がプラグイン本体より古いときに [WARN] と「sysrec を取得」ボタンを出すようになりました**（macOS）。
  - 従来の版数照合は **abi（CLI 契約の番号）だけ**を見ていました。abi は録音が根本的に壊れるとき（古いバイナリが新しい引数を黙って無視して 0 バイトの録音を作る等）にしか上がりません。**「abi は同じだが、後から直したバグを含む古いバイナリ」は素通り**していたのが今回の見落としです。
  - 録音エンジンの修正は `sysrec.swift` 側だけに入ることがあります（0.11.6 の 44.1kHz プツプツ修正がまさにそれで、TypeScript は 1 行も変わっていません）。BRAT が運ぶのは `main.js` / `manifest.json` / `styles.css` の 3 点だけなので、**本体を更新してもバイナリが古いと直りません**。
  - 版数が一致しているときの表示にも本体の版数を併記しました: `v0.11.7（abi 2 / 要求 2 以上）・プラグイン本体 v0.11.7`。

### 変更

- 版ズレは **[WARN]**（録音は可能）、abi 不一致は従来どおり **[NG]**（録音開始前に停止）の二段構えになりました。版ズレで録音自体を止めることはしません。

### 既知の制約

- **`sysrec` のコードが変わっていないリリースでも、版数が上がれば [WARN] が出ます。** `build.sh` が `manifest.json` から版数を刻むため、バイナリの版数はリリースごとに必ず上がるからです。機能的に入れ替え不要な場合でも「sysrec を取得」を促されますが、押せば解消します。取り残しを見逃すより促しすぎるほうを選びました（見逃したときの実害が 73 分の録音 1 本ぶんだったため）。
- 版数を読めないバイナリ（自前ビルドなどで `0.0.0` 形式でない場合）は比較せず、警告を出しません。誤検知を避けるためです。
- Windows は `sysrec` を使わない（アプリ内 WASAPI ループバック）ため、この診断項目はありません。

### 内部

- `isSysrecOutdated()` / `sysrecOutdatedMessage()` を `src/util/sysrecVersion.ts` に追加。比較は文字列ではなく major/minor/patch の数値で行う（`0.9.9` → `0.10.0` や `0.11.10` vs `0.11.9` が文字列比較では逆転するため）。
- `RecorderContext` に `pluginVersion` を追加し、`main.ts` の `buildContext()` が `this.manifest.version` を渡す。
- `src/doctor/diagnostics.ts` の `binary-version` チェックを ng / warn / ok の 3 分岐に。warn にも `downloadFix`（`releases/latest/download/sysrec` を取得）を付ける。
- 録音エンジン（`sysrec.swift` / webCapture / mix / normalize）は無変更。abi は 2 のまま据え置き。
