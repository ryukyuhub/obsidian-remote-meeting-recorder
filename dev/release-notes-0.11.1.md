## 0.11.1

### 修正

- **Bluetooth イヤホンなど 44.1kHz 出力のときに、録音が「わずかに速い＋0.25 秒ごとにプツプツ切れる」状態になる問題を修正**（macOS）。システム音タップが報告するサンプルレート（48000Hz 固定で返ることがある）ではなく、**集約デバイスの実レート**を取り込みレートに使うようにしました。
  - 実害の内訳: 44.1kHz を 48kHz と誤認すると、1 − 44100/48000 = **8.1%** ぶん実時刻に追いつけず、0.25 秒ごとに 10〜20ms の無音が挿入され、音そのものは 8.8% 速く（ピッチ +1.5 半音）なっていました。65 秒の録音で無音の挿入が 205 箇所。
  - 実測: 修正前 8.1% → 修正後 **0%**。440Hz のトーンが 440Hz で録れることを FFT で確認。
- **録音中に出力デバイスのサンプルレートが変わっても追従するようになりました**。BT イヤホンが通話モード（HFP 16kHz）へ切り替わるケースでは、従来は以降ずっと取りこぼし続けていました（実測 66.6%）。再接続に伴う欠落のみ（1〜3%）に収まります。
- **既定入力が Bluetooth のとき、マイクが 1 フレームも録れない問題を修正**（macOS）。`AVAudioEngine` の inputNode 経路は `engine.start()` が成功するのにバッファが流れてこないことがあり、**会議まるごとマイク無音**になっていました。既定入力でも CoreAudio IOProc 経路（特定デバイス指定と同じ経路）を優先します。
  - 実測: 同一デバイスで 0 フレーム → **287325 フレーム**。Obsidian 実機でも確認済み。
- **マイクが 3 秒間 1 バッファも取れないときは、もう一方の取得経路へ自動で切り替える**ようにしました（保険）。切替時はログに ⚠ を残します。
- **どちらかの系統が 1 フレームも取れなかった場合に ⚠ を必ずログへ残す**ようにしました。従来は `mic=0フレーム` が通常のログ行に埋もれていました。

### 変更

- 取りこぼし警告の文言を原因別に出し分けるようにしました。従来は一律「CPU 負荷が高い可能性があります」で、サンプルレートの取り違えを CPU 負荷と誤診する原因になっていました。
  - 録音中にレートが変わった場合 →「録音中に入力レートが変わりました（デバイス切替への追従ぶん）」
  - 実測入力レートが想定を下回る場合 →「実測入力 …Hz / 想定 …Hz — デバイスのサンプルレート不一致の可能性があります」
- ⚠️ **これは `sysrec` バイナリ側の変更を含みます。** macOS では doctor の「sysrec を取得」または `npm run build-sysrec` で更新してください。更新後は `--version` が `0.11.1` を返します。

### 既知の制約（修正不能・仕様）

- **Bluetooth イヤホンのマイクを選んで録音すると、録音中に聴こえる音とシステム音の録音が 16kHz 相当に落ちます。** イヤホンのマイクを開いた瞬間、macOS がイヤホンを A2DP（44.1kHz ステレオ）から HFP＝通話モード（16kHz モノラル）へ切り替えるためで、Bluetooth の仕様上どのアプリでも同じです。**会議では USB マイクや内蔵マイクを選んでください**（実測: USB マイク指定なら録音中もイヤホン出力は 44100Hz のまま）。

### 内部

- 手動 E2E チェックリストに **ROB-03e**（44.1kHz 出力で等間隔の無音が入らない）と **ROB-03f**（既定入力が BT でもマイクが録れる）を追加。
- IOProc 内のフレーム数計算をフォーマットの `bytesPerFrame` 基準に統一し、リアルタイムスレッドから可変プロパティを読まないようにしました。
- マイク取得経路の張り替えと停止をロックで直列化（watchdog との競合防止）。
- 取り込み統計を `LaneStats` に構造体化（実測レート・フォーマット変化回数を追加）。
