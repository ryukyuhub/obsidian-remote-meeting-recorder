## 0.11.8

Windows で**マイクは録れているのにシステム音声（会議相手の声）だけが無音**になったとき、録音中に気付けるようにしました。**録れない問題そのものを直すリリースではありません**（回避策は下記「既知の制約」）。

報告は「Google Meet（ブラウザ）を録音したらマイクは入っていたが相手の声が無音。Teams は録れる」というものです。Windows のシステム音声は Electron の `audio: "loopback"` で取っており、Chromium の実装上これは **Windows の「既定の再生デバイス」1 本だけ**を録音します（Chromium ソース上の事実）。Meet の音が「既定の通信デバイス」や Meet で選んだ別のスピーカー、Bluetooth ヘッドセットのハンズフリー端点などへ出ていると取りこぼします。**今回の Meet の事例がこれによるものかは実機で確かめられておらず、最有力の仮説にとどまります。** さらに従来の開始直後の無音警告は「システム音声とマイクの**両方**が 0」のときしか出なかったため、片方だけ無音の状態に気付く手段がありませんでした。

### 改善

- **開始直後の無音警告を、ソースごとに判定するようにしました**（Windows）。
  - 両方 0／マイクだけ 0 … 従来どおり開始から **5 秒**で警告します。両方 0 のときは 1 回にまとめ、後からシステム音声だけを重ねて知らせることはしません。
  - **システム音声だけ 0 … 開始から 20 秒**で知らせます。会議前に録音を始めた・開始直後に誰も話さない、といった正常な状況でもループバックは厳密に 0 になる（マイクと違い環境ノイズが乗らない）ため、5 秒では誤警告が多くなるからです。
  - 警告はソースごとに最大 1 回です。録音は止めません。
  - システム音声だけ 0 のときは、状況で文言の強さを変えます。
    - **既定の再生デバイスと既定の通信デバイスが別の機器だと分かっている**とき: 「⚠ システム音声のレベルが 0 のままです。会議の音声が録音されていない可能性があります（録音自体は継続しています）。」に続けて、**両デバイスの名前**と「会議アプリ（ブラウザの Meet など）のスピーカー設定を『既定』に合わせてください」を出します。
    - 同じ機器、または判定できないとき: 「システム音声のレベルが 0 のままです。会議の音声がまだ流れていなければ問題ありません」と、録音元の既定の再生デバイス名を出します（⚠ なしの控えめな通知）。
- **診断（doctor）に「システム音声の録音元（再生デバイス）」を追加しました**（Windows）。「システム音声（ループバック）」の次に表示されます。
  - 既定の再生デバイスと既定の通信デバイスが**別の機器なら [WARN]**。両デバイスの名前と、会議アプリのスピーカーを「既定」に合わせる方法・Windows の「サウンド」設定で既定の通信デバイスを既定の再生デバイスと同じ機器にする方法を案内します。
  - **同じ機器なら [OK]**（「既定の再生デバイス『…』の音を録音します（既定の通信デバイスも同じ機器です）。」）。
  - デバイス名が取れないなどで**判定できなければ [INFO]**（システム音声は既定の再生デバイスだけを録る旨の案内のみ）。
- 録音開始時に、開発者ツールの Console へシステム音声トラックの label・`getSettings()`・既定／通信の再生デバイス名を記録するようにしました（Windows）。ずれがあれば `console.warn`、無ければ `console.debug`。原因調査用です。

### 変更

- 診断（doctor）の実行が非同期になりました。Windows では結果が出るまで「診断中…」と表示されます（macOS は従来どおり即時に表示）。デバイス名の取得のため、Windows では再生デバイスの名前が空のときに一度だけマイクを一瞬開いて名前を解錠します。応答が無くても **4 秒**で打ち切り、診断は止まりません。
- システム音声だけを録る録音（音源=システム音声）でも、無音の警告は 5 秒ではなく 20 秒で出るようになりました。
- 既定と通信がずれているだけでは、録音開始時に警告を出しません。ずれていても会議アプリが既定の再生デバイスへ出していれば実害は無いので、毎回の警告や無音警告との重複を避けるためです。ずれは診断と、実際にシステム音声が 20 秒無音だったときの警告で知らせます。

### 既知の制約

- **システム音声が録れない状態そのものは直っていません。** Windows でシステム音声が無音になる場合は、次のどちらかで回避してください。
  - 会議アプリのスピーカーを「既定」にする（Google Meet なら 設定 → 音声 → スピーカー を「既定」に）。
  - Windows の「サウンド」設定で、**既定の通信デバイスを既定の再生デバイスと同じ機器**にする。
- ずれの検出は Chromium が `enumerateDevices` で出す擬似エントリ `default`（既定）と `communications`（通信）の比較で行います。**会議アプリ側でスピーカーを個別に選んでいる場合（既定・通信のどちらでもない機器）は検出できません**。この場合も 20 秒のシステム無音警告は（控えめな文言で）出ます。
- デバイス名が取れないと判定不能になります。特に**音源=システム音声のみ**の録音ではマイクを開かないため、録音開始時の判定は名前が空のまま判定不能になりやすく、無音警告は控えめな文言になります（診断では名前の解錠を試みます）。
- 会議前に録音を始め、20 秒以上誰も話さなかった場合も、システム音声の控えめな通知が 1 回出ます。
- **macOS の挙動は変わりません**（sysrec 経路・`sysrec` のコードも無変更）。ただし 0.11.7 の既知の制約どおり版数が上がるため、macOS の診断で `sysrec` の版ズレ [WARN] が出ます。「sysrec を取得」を押せば解消します。

### 内部

- `src/audio/webDevices.ts` に `getOutputRouting()` と純関数 `outputRoutingOf()` / `realDeviceNameOf()` を追加。擬似エントリのラベル（「Default - スピーカー (…)」「既定 - …」「通信 - …」など）は最初の ` - ` より後ろを実デバイス名として比べる（接頭辞は言語で変わるので照合しない。` - ` の無いラベルは判定不能）。groupId は、`default` と `communications` の両方が実デバイスの groupId と対応づくときだけ比べる。**名前と groupId のどちらかが違えば「ずれ」**とする。Bluetooth ヘッドセットのステレオ端点とハンズフリー端点のように、groupId が同じでも名前が違う組み合わせを拾うため。
- 文言の部品 `defaultOutputPhrase()` / `loopbackSourceHint()` を同ファイルに置き、無音警告と診断で共有。
- `WebRecorder` の `onSilence` を `(sources, outputRouting)` を受け取る形に変更。`startSilenceWatch()` がソース別に判定し、文言は `src/recorder/backend.ts` の `webSilenceMessage()` で出し分ける。
- `src/doctor/diagnostics.ts` に `output-routing` チェックを追加し、`windowsDoctor()` を async 化。`DoctorModal` は再診断の世代番号で古い結果を捨てる（連打対策）。
- 手動 E2E に **WIN-11**（既定／通信のずれの診断と無音警告・回避策の効果）を追加し、WIN-06 の期待値を新しい挙動に更新。
